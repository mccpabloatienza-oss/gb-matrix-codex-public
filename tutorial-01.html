Tutorial en español

De una pregunta comercial a un sistema de decisión comprobable

Una pregunta empresarial puede convertirse en un artefacto utilizable, revisable y mantenible. Este tutorial muestra el recorrido de GB Matrix (Matriz GB), una herramienta que nació con ChatGPT a partir de experiencia real de marketing y luego inspiró una demostración técnica independiente desarrollada con Codex.

1. Formular una decisión, no una pantalla

Empezamos por dos preguntas: ¿qué productos tienen tracción real de demanda? y ¿qué inventario merece atención? El resultado buscado fue un mapa ITD × IRI, con cuadrantes y justificaciones consultables. El negocio definió qué significa una decisión útil; el código permitió hacerla repetible.

2. Elegir indicadores con criterio y contrastarlos

La herramienta original atravesó revisiones de indicadores, ventanas temporales, comparaciones y backtesting. Los datos faltantes, la estabilidad y las discrepancias de fuentes influyeron en cómo interpretar cada resultado. Aprendizaje: antes de automatizar una clasificación, hay que definir en qué condiciones es confiable.

3. Incorporar conocimiento del producto en la arquitectura

En el artefacto comercial real, surgió la necesidad de distinguir entre un identificador exacto de SKU y una familia comercial. En dos contextos reales anonimizados como Brand 1 y Brand 2, algunas familias requirieron interpretar conjuntamente código, título normalizado, categoría y modelo. Así aparecieron dos escalas analíticas: SKU y familia. Esta característica pertenece al artefacto privado original; la demo pública no implementa agrupación de familias.

4. Pedirle a Codex una demostración reproducible y segura

El brief para Codex priorizó separación de responsabilidades, datos generados desde cero, validaciones, actualizaciones mensuales, trazabilidad y pruebas. La demo utiliza indicadores genéricos y marcas ficticias, con una semilla fija de generación. La versión empresarial permanece separada y privada.

Ejemplo didáctico de instrucción (resumen pedagógico, no transcripción literal del prompt original):

Construí una demo independiente con datos 100 % sintéticos.
Separá indicadores, interfaz, importación y validación.
Mostrá demanda vs. inventario y ficha detallada.
Permití importar un período CSV y conservar snapshots.
Agregá pruebas de casos válidos y fallidos en CI.
Documentá claramente qué decisiones aporta el usuario.

5. Ejecutar, comprobar y corregir

El repositorio permite repetir localmente la generación, los tests, los chequeos de sintaxis y la auditoría de patrones:

npm run generate
npm test
npm run check
node scripts/audit_public_repo.js
python -m http.server 8000

Después abrí http://localhost:8000. El reporte de GitHub Actions registra 15 pruebas aprobadas y cero fallidas. También se añadieron pruebas para que textos similares a HTML provenientes de archivos importados se muestren de forma segura. La auditoría personalizada examinó 38 archivos sin encontrar patrones definidos como riesgos.

6. Analizar el resultado, no solo hacerlo funcionar

Probá los filtros, cambiá de período, elegí un producto y revisá su historial y cuadrante. Para estudiar las actualizaciones, inspeccioná el módulo mensual, los tests y el reporte. La selección y aplicación del CSV mediante el cuadro nativo del navegador sigue con una comprobación manual pendiente en Issue #4; las rutas de procesamiento tienen cobertura automatizada.

Resultado de aprendizaje: un experto comercial puede definir preguntas, reglas, límites y criterios de aceptación; Codex puede transformar esos requisitos en código que se puede revisar, ejecutar y probar. La calidad del sistema depende de ambos.
English tutorial

Building a testable business artifact with Codex

Starting point. GB Matrix began as a real business decision tool developed with ChatGPT and guided by domain expertise. It connects demand traction (ITD) with inventory relevance (IRI), using product details, filters, evidence and review statuses to support portfolio decisions. A separate Codex project turns the same generic concept into a public, reproducible synthetic demonstration.

1. Define the decision

Specify the business question and what a useful answer must show. In GB Matrix, the core decision combines demand and inventory into quadrants, then provides product details and supporting data to review the result.

2. Challenge the first metrics

The original work compared alternative indicators and time horizons, used backtesting and reconciled conflicting sources. The lesson for prompting is to ask for validation criteria and failure conditions before asking for a final dashboard.

3. Let business reasoning shape data structures

The original commercial artifact added a dual SKU/family analysis after the author identified cases where an exact SKU could not describe a meaningful product family. Brand 1 and Brand 2 are anonymized real business contexts. That distinction became a second view in the historical private system and is not an implemented feature in this public synthetic demo.

4. Direct Codex with constraints

The development brief specified wholly synthetic data, modular source, transparent demonstration formulas, import validation, period history, reproducible tests, CI and an honest attribution trail. The product expert supplied the priorities and acceptance criteria.

5. Verify reproducible engineering

Run npm run generate, npm test, npm run check and node scripts/audit_public_repo.js; serve the folder locally and explore the UI. The verified CI run reports 15 passing tests, 0 failures and a custom audit of 38 files with 0 rule-based findings. The native CSV browser chooser awaits a separate manual end-to-end test.

6. Review the trail

Compare the original Codex demo PR, the human decisions, the development log, the test suite and the QA issue. Every claim in this lesson is tied to an inspectable artifact or clearly labeled historical author account.

Takeaway: Codex makes it possible to build and maintain software through explicit domain requirements, verifiable tests and iterative engineering. The business expert remains responsible for the interpretation and commercial purpose of the system.
